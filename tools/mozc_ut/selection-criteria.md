# 調整の案と判定基準（結果を見る前に固定、2026-11-04）

調整に使う集合は開発用だけ: Phase 3a 開発用30文（かなだけの22文）、Mozc同梱の quality regression（oss、regression、myoji）、前回の15語。試験用A（Phase 2c 54文）、試験用B（AJIMEE-Bench）は流さない。

## 案（変えるのはsudachidictの語だけ。personal-names、place-namesは全案で同じ）

| 案 | 内容 |
| --- | --- |
| V0 | 前回の版（sudachidictのコスト 9000 + c//20） |
| A1 | sudachidictのコストを 10000 + c//20 |
| A2 | sudachidictのコストを 11000 + c//20 |
| B | 人名・地名らしい語を除く: 表記がpersonal-namesかplace-namesの表記と同じ語、または表記と読みの先頭がMozcの姓（id 1923 名詞,固有名詞,人名,姓）の表記と読みに一致し、残りが1文字以上ある語 |
| C1 | 読みがMozcの既存辞書に一つでもある語を除く（新しい読みだけを足す） |
| C2 | 読みがMozcの既存辞書に5種類以上の表記を持つ語を除く |
| BC2 | BとC2の両方 |

## 指標

- quality regression の合格率（oss、regression、myoji × desktop、mobile）
- 開発用22文の全文第一候補の一致数
- 15語の「上位10件への割り込み」の数: Uzumiの絞り込み後の候補一覧の先頭10件のうち、追加前の先頭10件に無い候補の数（15語の合計）。前回の不自然な語（揮洒、母健、有賀桃、す今仙）はすべてこれに当たる。語の自然さを人が判定しない機械的な基準とする。
- 前回の改善の保持: 五千円札・二千円札・一万円札（oss）、藪から棒に（regression）、VN02「雪が降る」が合格のままか

## 選び方（この順に比べる）

1. 前回の改善の保持（上の5項目）を落とさない案に限る。
2. 割り込みの数が少ない案。
3. oss＋regression の mobile 合格数が多い案。
4. myoji mobile の合格数が多い案、次に desktop の合計。

## 追記: 結果を見た後に選び方を変えてA1を採った（2026-11-04、ユーザーの決定）

上の選び方を当てると案C1になった。結果（`variants_summary.md`）を見た後、ユーザーが選び方を変えて案A1を採ると決めた。上の本文は書き換えていない。

理由（ユーザーの説明）: A1が外れたのは、1番目の条件のうちVN02（雪が降る）1文の改善を失った点だけである。oss、myoji（Uzumiの変換はdesktop型のRequestなので、desktopの結果が近い）、前回の悪化の回復（ひるごはん、りくおう）ではA1が上回り、C1はmyoji desktopで追加前を下回る。

この採用は、開発用の集合の結果を見てから決めたものである。以後、この開発用の集合（Phase 3a開発用30文、Mozcのquality regression、前回の15語）での辞書の比較は、調整に使った集合での値として扱う。
