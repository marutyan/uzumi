# 自動測定の道具・版3の確認

2026-09-24に、自動測定の道具`tools/phase2c/run_automated.py`の版3が、旧い版と同じ結果になるかを、[評価条件](phase2c-evaluation-protocol.md)の「道具の版」の手順で確かめた。

## 結論

- 比べた課題は、練習6文（条件O・N）と開発用の30文のうち先頭の10文（条件N）の計22件である。課題ごとの最終正解、各操作数、`display_changes`・`flicker`、状態の変化、送った押下の数、訂正の手順の記録は、22件すべてで一致した（食い違い0件）。flickerも一致したため、`--repeat-old`による同じ版での揺れの確認は行っていない。
- 開発用の課題では、←で文節へ移る手順（`left`）が4課題で計8回あり、版3で加えた待ち（候補の取り直しの結果を待つ）を通っている。伸縮と候補一覧（∨）を使って最後まで終えた課題は無い（下の「止まった課題」）。
- 1課題あたりの時間（次の課題の開始までの差の中央値）は、旧い版に比べて版3で短くなった。練習6文では条件Oが22.3秒から15.5秒、条件Nが17.1秒から12.9秒、開発用の10文（条件N）では25.9秒から19.0秒だった。
- 開発用の30文の11文目（VP03）で、両方の版が同じ所で止まった。候補一覧を開いた後に、試験欄が画面の読み取りから消えたためである（アプリ側の原因は未確認）。残りの20文（条件N）と、開発用の30文の条件Oは比べていない。

版3を本測定に使う前に、止まった課題の原因を確かめ、残りの課題で同じ比較をすることを勧める（要確認）。

## 版3で変えたこと

版2の待ち方（状態の確認口`EVAL_STATUS`で、送った押下の受け取りと変換の仕事の終わりを2回続けて読めるまで待つ）に、Phase 2cの版2の結果で加えた伸縮・過去訂正・候補一覧の全範囲読みの手順を合わせたものを、版3とした（`TOOL_VERSION = 3`）。

加えた待ちは次のとおりである。

- ←で文節へ移った後、伸縮の長押しの後、候補一覧（∨）を開いた後は、次の待ちで`candidates_outstanding`が0になるまでも待つ。
- エンジンは英数字だけの読みなどでは取り直しの結果を返さず、IMEの結果待ちは次の依頼まで真のまま残る。そこで、変換の仕事が0のまま結果待ちが3回続けて読めたら、結果は来ないとみなして待ち終える。結果はworkerの仕事が終わる前にUIスレッドへ積まれるため、仕事が0になった後の読み取りで結果待ちが残っていれば、結果は届かない。
- 明示変換（条件O）では`candidates_outstanding`は常に0で、待ち方は版2と同じである。

長押しの伸縮は、IMEが1回の長押しを1押下と数えるため、道具も送った押下を1と数える（版2と同じ）。

### 止まった課題（VP03）

両方の版とも、VP03で「試験画面が前面でない」として止まった。止まった時点では、試験画面の窓は前面で入力の対象のままだったが、窓の中身が読み取りに出ず、試験欄が見つからなかった。このとき入力方式の窓は、画面の上端（状態表示の下）から下端までを覆っていた。道具は、訂正中の文節に目標の候補が候補バーに無かったため、候補一覧（∨）を開いた直後である。候補一覧を開いたときに入力方式の窓が画面全体へ広がり、試験画面の中身が隠れた可能性があるが、確かめていない（推測）。

別のアプリは前面に出ていない。止まった後は何も入力せず、次の手順で試験画面を開き直した。
