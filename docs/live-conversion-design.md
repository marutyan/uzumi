# ライブ変換と編集状態の設計案

この文書はPhase 0の提案である。API上の根拠は[Android調査](research/android-platform.md)、UXの評価は[評価計画](research/ux-and-evaluation.md)を参照する。

## 所有する範囲

IMEが保持する一つのcompositionを訂正可能な範囲とする。Android Editorには表示文字列を送り、IME内部には読みとsegment対応を残す。「安定した変換」と「Editorへ確定済み」を区別する。

| データ | 用途 |
|---|---|
| sessionEpoch | フィールド・接続・機密方針が変わるたびに更新し、古い書込みを拒否する |
| revision | 読み、候補選択、カーソル、Undo/Redo、境界、設定変更で更新する |
| composition | 読み、表示文字列、Editor上の開始位置、selection、同期状態を保持する |
| segment | 識別子、読みの範囲、表示の範囲、変換文字列、保護状態、候補を保持する |
| request identity | sessionEpoch、revision、読み、対象範囲、保護範囲、辞書/モデル世代を保持する |
| operation history | 同期が確認できるcomposition内の変更前後と操作種別をメモリ上で保持する |

読みの編集は書記素を基準にし、AndroidとのoffsetはUTF-16で明示変換する。文字数比率で読みと表示を対応付けない。変換器が内部alignmentを返さない場合はsegment境界だけを信頼する。

## segmentの状態

| 状態 | 自動更新 | 遷移の提案 |
|---|---|---|
| provisional | 現在の読みと保護範囲に整合する結果に限り許可 | 入力中の末尾segment |
| stable | 自動更新を禁止 | 次segmentへ進み、異なる読みrevisionをまたいで同じ結果が維持された場合 |
| chosen | 自動更新を禁止 | ユーザーが候補を選択した場合 |

安定化の初期実験案は「後続segmentへ進んだ」かつ「独立した3回の読みrevisionで同じ表記・読み範囲を維持」。同じ入力への辞書結果とニューラル結果を2回分に数えない。回数、末尾の保持長、時間制限はUX試験で決める仮値であり、信頼度の校正済み推定ではない。

stable/chosenに関わる境界をまたぐ再分割・再変換は拒否する。ユーザーがそのsegmentの読みを編集すると、編集範囲だけprovisionalへ戻し、必要な隣接範囲をUIで示す。候補選択はchosenへ直接遷移し、文全体を確定しない。

## 非同期結果の適用

キーの視覚応答と読みの更新は推論を待たない。変換はUIスレッド外で実行し、結果適用とEditorへの書込みを一か所で順序付ける。

結果のsessionEpoch、revision、読み、対象範囲、保護状態、辞書/モデル世代が現在値と一致し、接続が有効な場合だけ適用する。候補のタップも候補を表示したrevisionとsegment識別子を照合する。cancelだけに依存せず、停止できなかった古い推論も捨てる。

最新要求だけを待ち行列に残し、同時に走るニューラル推論を制限する。時間超過・モデル不在・メモリ不足時は現在の安全な候補または読みを保ち、遅れて戻った結果による更新を行わない。モデル異常で入力サービスを巻き込まない構成の必要性は実装試作で判断する。

ニューラル結果は末尾provisionalだけを改善する。表記を一度変えるたびにflickerとして記録し、短い入力での適用待ち時間・改善閾値を試験する。モデル出力に読みの欠落・重複、数字・記号の改変、範囲不整合があれば適用しない。

## 訂正・カーソル・削除

候補バーは現在のsegmentの訂正候補を常時表示する。IME内で横にたどれるsegment一覧と前後選択を用意し、長文でも末尾以外へ到達できるようにする。エディタのselection通知がcomposition内の一点を示すときは、その位置に対応するsegmentを編集対象にできる。

候補選択前の入力位置を保持し、過去segmentの訂正後は末尾入力へ戻れる操作を用意する。アプリ側の文字列をタップして必ず同じ動作になることは保証しない。範囲選択、composition外への移動、Editor側置換は通常編集へ安全に切り替える。

「よい→良い」はsegmentの読み「よい」を保持する。末尾Backspaceは読み末尾の書記素「い」を削除して「よ」を再変換する。表示「良」の内部位置からどの読み位置か決められない場合は、該当segmentを読みへ戻し、削除せず位置を選べる状態を第一案とする。この一手はUndo可能にし、自然さを利用試験で確認する。

確定済みの通常文字列の削除では、取得できる周辺文字列の書記素境界を使う。code point削除APIだけでZWJ絵文字・結合文字のまとまりが保証されるとは考えない。読み取得が失敗した場合に見えない範囲を推測して大量削除しない。

## 境界とEditor action

| きっかけ | 提案動作 |
|---|---|
| `。！？` | 句読点を含む現在表示を確定し、古い推論・Undo範囲を終了する |
| `、` | 直前をstableにするsoft boundary。compositionと限定した文脈は残す |
| 改行キー | multi-lineかactionかをEditorInfoから判定。文字としての改行なら確定後に一度挿入する |
| Send/Search/Done/Next | 有効な同じ接続へ確定処理後、一度だけ対応actionを送る。改行を重ねない |
| 外部のフィールド移動 | 旧接続を直ちに無効化。新接続へ旧compositionを送らない。旧文字の確定結果はEditorの挙動に依存する |
| ライブ変換OFF | 所有中の表示を一度確定し、新入力を明示変換モードへ切り替える |
| 長すぎるcomposition | 安定した前方範囲の自動確定を検討。上限は試験後に決め、過去訂正範囲が短くなることを示す |

句読点を含むURL等の扱いは、text variationと入力モードを使い試験する。自動変換を避けるURL・email・password等へ同じ境界規則を無条件に適用しない。

## Undo / Redo

候補の誤選択は一操作として戻す。自動変換だけでUndo stackを埋めず、起点の入力操作にまとめ、Undo時にその入力・表示・保護状態を復元する。長押し削除、濁点/小文字変更、segmentの読みへの復帰も意味のある操作単位にする。

Undo/Redoでrevisionを進め、実行中の推論と表示済み候補を無効化する。新しい入力を行ったらRedoを消す。復元直後の再推論でUndoした表示を即座に上書きしないよう、次の読み編集まで復元した範囲を保護する。

確定済み文字列のUndoはMVPの保証外。将来試す場合も、同一接続・範囲・周辺文字列の一致を確認できる場合に限定し、不一致や情報不足では中止する。Androidのbatch editをtransactionやrollbackとして扱わない。

## 接続喪失・再作成

compositionはメモリにだけ保持する。process recreation後に古い文字列を自動再送しない。回転・restartInputでは接続を再評価し、Editor上のcomposition/selectionと一致を確認できた場合だけ状態を再利用する。候補・モデル応答の世代を無条件に引き継がない。

password/PIN、sensitive、IME_FLAG_NO_PERSONALIZED_LEARNINGでは、学習・履歴・ニューラル文脈利用を止める安全側の方針とする。通常欄から移った時点で待機中の処理を無効化し、一時文脈を破棄する。ログに本文・候補・clipboardを残さない。

## 反証する試験

- 入力Aの推論が入力Bより後に終了しても、Bを上書きしない。
- 候補選択後の境界変更、Undo後の結果、辞書更新前の結果を拒否する。
- Send直後・別アプリ移動直後・password移動直後に結果が届いても書き込まない。
- 「今日は｜天気が｜いいですね」で「転機が」へ直しても他segmentと末尾入力位置を壊さない。
- 「よい→良い」、結合濁点、サロゲート、ZWJ絵文字、範囲選択、長押し削除を試す。
- 返り値false/null、selection通知遅延、アプリ側置換、回転・プロセス終了で二重送信しない。
