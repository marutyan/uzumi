## 測定の前に決めた手順

### 版1と同じにするもの

- 評価条件の固定版：commit `332d6c8`。
- 準備処理：各条件の開始前に、Uzumiを止めてプロセスが無いことを確かめてから、IME側の学習（`learning.tsv`）とMozcの学習（`segment.db`、`boundary.db`、`history.db`、`.history.db`、`cform.db`）を消す。消えていなければ測定を始めない。ユーザー辞書は無い状態から始める。
- 実施順：条件O、条件Nの順に、54文を同じ順番で1回ずつ流す。順番はseed `20261001`で、リストA・B・Cの順に各リスト内を並べ替えたもの（`python3 tools/phase2c/run_automated.py order`）。
- 入力の方法：押下の送り方、キーの間隔150 ms、面の選び方、終端操作は版1と同じ。
- 過去訂正：評価条件どおり、読みを句点まで入力してから前の語を直す手順（版1の再測定で入れた手順）を本測定で使う。完了時間は、版1の再測定と同じく、最初の押下の直前から最後の押下の直後までを端末の時計で測った値（終点を揃えた値）も残す。
- 候補の探索：候補バーに目標が無ければ候補一覧（∨）を開き、新しい候補が出なくなるまでスクロールして全範囲を読む（版1の誤答の確認で入れた手順）。

### 版2で加えるもの：文節の区切りの伸縮

新しい版では、変換中に←→を長押しすると、対象の文節の終わりが一書記素ずつ縮む・伸びる（押してから400 msで1回目、以後300 msごと）。条件Nでは候補バーの対象の文節、条件Oでは先頭文節が対象である。訂正の「必要な操作数の下限」の手順に、次の規則で伸縮を加える。両条件に同じ規則を当て、左右だけを入れ替える。

**使う場面。** 対象の文節の候補の全範囲（候補バーと、候補一覧をスクロールして読んだ全体）に、目標に合う表記が無い場合だけ使う。候補で直せる場合は伸縮しない。

**目標の語の始まり。** 目標の表記を読みへ対応付け（かな・記号は読みの同じ一文字、続いた漢字などは読みの1文字以上）、次の読みの位置を「語の始まり」とする。

- 読みの先頭（過去訂正の打ち直しでは、打ち直した部分の先頭）
- 句読点の直後
- ひらがなの直後に、漢字・カタカナ・英数字が始まる位置

**文節の読みの求め方。** 条件Nで過去の文節を訂正中は、候補バーの左端の札（訂正中の文節の読み）を使う。末尾の文節と条件Oの先頭文節は、候補のうちかな・カナの表記を読みへ直したものを使う。読みを求められなければ伸縮しない。

**条件N（末尾側から直す）。** 対象の文節より右は、目標と一致を確かめ済みである。そこで文節の終わりは正しいとみなし、始まりを見る。

1. 文節の始まりが語の始まりでない（語が前の文節とまたがる）場合：「←」で前の文節へ移る。その語の始まりが前の文節の内部にあれば、そこまで前の文節を縮める。前の文節がその語の始まりから始まる場合は、語の終わり（次の語の始まり、または対象の文節の終わり）まで前の文節を伸ばす。
2. 文節の始まりが語の始まりで、文節の内部に語の始まりがある（二語以上を含む）場合：内部の最後の語の始まりまで、対象の文節を縮める。末尾側の語が別の文節になる。
3. どちらでもなければ伸縮しない（区切りは規則上合っている）。

伸縮の後は「末尾」で入力位置へ戻り、末尾から照合し直す（候補を選んだ後に右側が変わった場合と同じ扱い）。

**条件O（先頭から直す）。** 先頭文節の始まりは、確定済みの前半の直後で正しい。そこで終わりを見る。

1. 文節の終わりが語の始まりでない（語が次の文節とまたがる）場合：その語の始まりが先頭文節の内部にあれば、そこまで縮める。無ければ語の終わり（次の語の始まり、または読みの終わり）まで伸ばす。
2. 文節の終わりが語の始まり（または読みの終わり）で、文節の内部に語の始まりがある場合：内部の最初の語の始まりまで縮める。先頭側の語だけが先頭文節に残る。
3. どちらでもなければ伸縮しない。

伸縮の後は、新しい先頭文節の候補を同じ手順で探す。

**長押しの送り方と数え方。**

- k書記素の伸縮は、1回の長押しで行う。押す時間は、k回目と(k+1)回目の繰り返しの中間（400 + 300×(k−1) + 150 ms）とする。
- 評価用計数は、1回の長押しをキー1・訂正1と数える。同じ長押しで繰り返した伸縮は数えない（PR #22の計数）。これは指標の定義（画面に触れた回数）と同じである。
- 伸縮の後、訂正中の文節の読みの札で結果を確かめる。ずれていれば、長押しを1回だけ足して合わせる（`resize-adjust`）。この長押しも数える。
- 規則による伸縮は、1課題で3回までとする。

**評価条件との関係（要確認）。** 評価条件は、自動測定で「長押しを含む操作は使わない」としている。これは`input tap`の遅れで削除キーが連続削除に入るのを避けるための規則である。伸縮は長押しでしか行えないため、版2では←→の長押しに限って使う。削除キーは版1と同じく、押下時間を固定した短い押下で送る。

### 誤答の原因の分類

最終文が誤った課題を、手順の記録（`fix_steps`）から次の3つに分ける。確認できるのは、道具が最後に直そうとした文節についてだけである。

| 分類 | 条件 |
|---|---|
| 候補の全範囲に無い | 候補の全範囲に目標が無く、区切りは規則上合っていた（`resize-none`の後に`no-candidate`）。その課題で伸縮をしていない |
| 区切りの誤り | その課題で規則による伸縮をしたが、最終文が誤りのまま。または伸縮の上限で止まった |
| その他 | 上のどちらでもない（文節や読みを特定できない、対応付けできない、手順の上限など） |

## 誤答の原因

測定の前に決めた分類の規則で分けた。確認できるのは、道具が最後に直そうとした文節についてだけである。

| 条件 | 分類 | 件数 | 課題 |
|---|---|---:|---|
| O | 候補の全範囲に無い | 0 | — |
| O | 区切りの誤り | 0 | — |
| O | その他 | 3 | U03、U05、U06 |
| N | 候補の全範囲に無い | 0 | — |
| N | 区切りの誤り | 0 | — |
| N | その他 | 1 | U03 |

「その他」の4件は、どれも同じ形である。

- 候補一覧を全範囲読んでも、目標に合う候補が無かった（`grid-absent-full`）。
- 文節の読みをかな・カナの候補から求められず、区切りが目標と合っているかを判定できなかった（`resize-no-reading`）。

つまり「候補の全範囲に無い」ことは確かめたが、区切りの誤りかどうかは判定できていない。4件ともURLの課題であり、英数字の文節ではかな・カナの候補が出ないため、この規則では読みを求められない。表示が誤った理由は確かめていない。

## 限界

- **残りの課題の学習の状態が、本測定の続きとは違う。** 本測定の条件Nでは、各課題は前の課題の入力の学習が残った状態で流れた。残りの8課題は、学習を消した状態から、C03を先頭にして流した。版1の同じ8課題は本測定の続きで測ったため、この8課題の版1との差にも学習の状態の違いが入る。
- **自動入力であること。** 人の指の操作数、打ち間違い、訂正の探し方、主観は含まない。訂正操作数は、機械的な手順による「必要な操作数の下限」である。伸縮は、目標の表記から決めた位置へ1回の長押しで行う。人がこの位置を見つけるまでの試行は含まない。
- **伸縮の規則の範囲。** 「語の始まり」を、ひらがなの後に漢字・カタカナ・英数字が始まる位置で近似している。ひらがなだけの語の境界と、漢字の後の漢字の境界（例：「3時」と「15分」の間）は扱えない。英数字の文節では読みを求められず、伸縮しない（条件Oで3件、条件Nで1件）。
- **評価条件の版。** 版2は評価条件第2版（伸縮のための←→の長押しを使う）で測った。版1は固定版で測り、長押しを使っていない。使ったのはD01の1回だけで、D01を除いても判定は変わらない（「結論」を参照）。
- **完了時間には自動化の待ち時間が入る。** 版1と同じく、変換・訂正の手順ごとに約0.8秒待ち、画面を2〜3回読む。伸縮の後は読みの確認のため、さらに読み直す。完了時間の比は、人の入力の速さの比較としては使えない。
- **直せなかった課題の操作が数に入っている。** 候補一覧の開閉と、文節を探す「←」は数に入る。候補一覧のスクロールは数に入らない。
- **「過去の正解の破壊」は判定していない。** 途中の表示を記録しないためである。H3の「反証なし」は、完了した課題の計数に限る。
- **版1との比較は、アプリと道具の両方が違う。** 改善のうち、アプリの変更と道具の変更（伸縮）の寄与は分離していない。
- **D05は2回とも測れていない。** 訂正の途中で試験画面を読めなくなる道具側の止まり方で、候補一覧が画面を覆うためと考えられる（推測）。
- **図は無い。** Macの既存のPythonにmatplotlibが無いため、表だけで示した。
- `getDataVersion()`の値は記録していない。
